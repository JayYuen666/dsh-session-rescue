# 会话自动接续

把卡住的回合捞回来：提供方瞬时失败后重发、输出被截断时继续、待办没闭合就接着补跑。

## 设置卡上改的是什么

三组互不相干的自动动作，各有各的等待、单会话冷却与配额。等待时间按秒录入、按毫秒存。

- **总开关** — `enabled`（默认开）关闭后三类自动动作与请求级 429 重试全部停止，只剩手动入口（停止并重问、编辑重发、重试、发送续写与「继续中断的回合」）。
- **瞬时失败自动续跑** — `resumeDelayMs`（1–300 秒，默认 10）是宿主自己的重试跑完之后再等多久。`resumeCooldownMs`（5–3600 秒，默认 120）是同一会话两次接续之间的最小间隔。`maxResumes`（0–20，默认 3）是同一会话**连续**接续的次数上限：任一 `completed` 回合会把它清零，`0` 表示不自动续跑。`chainResumeDelayMs`（1–300 秒，默认 60）用于链式失败：延迟取它与 `resumeDelayMs` 的较大者，并跳过冷却窗口；配额与 `providerExcludes` 仍然生效。
- **输出截断自动继续** — `continueDelayMs`（0.5–300 秒，默认 3）、`continueCooldownMs`（5–3600 秒，默认 60）、`maxContinues`（0–20，默认 3，同样按连续回合计数：任一 `completed` 回合清零，`0` 表示不自动继续）。
- **待办未闭合自动补跑** — `resumeOnOpenTodos`（默认开），配 `unfinishedDelayMs`（1–300 秒，默认 5）、`unfinishedCooldownMs`（5–3600 秒，默认 120）、`maxUnfinished`（0–20，默认 2）。只有回合以 `completed` 收尾、且该回合自己写过的待办清单仍未闭合时才触发；`aborted` / `interrupted` 或调用过 `ask_user_question` 的回合不补跑。这份配额只在清单闭合时归还，清单一直不闭合就停在 `maxUnfinished` 上限。另有一个可开的实验开关 `unfinishedSteerMode`（默认关）：回合将收尾而清单仍未闭合时，先在同一回合内经 `agent.steer` 续做，而不是收尾后再补跑——与补跑共用同一份 `maxUnfinished` 配额。
- **排除路由** — `providerExcludes`（默认空）里写明的提供方路由不会自动触发瞬时失败续跑（`resume`）；截断继续与待办补跑不看这一项。匹配是对 provider 字符串做精确、区分大小写的比较，没有通配或前后缀匹配。

以上都是每次判定现读，改完不需要重启宿主。

## 卡上没有的

输入框上方那个按会话的开关与各组已用次数只存在于运行期内存：宿主重启后计数归零、各 kind 的冷却时间戳一并清空（等于把冷却闸门打开一次），按会话开关回落到全局 `enabled`。

回合级手动动作（编辑重发 / 重试 / 发送续写，以及「继续中断的回合」）挂在最新完成回合的尾部；输入框上方的 dock 只保留倒计时横幅、停止并重问与每会话开关。自动配额耗尽会在 frame 级弹一次提示（按 会话 / 轮次 / 类别 去重，不持久化）；关掉该会话的开关同时撤掉宿主侧的耗尽位。

`requestRetryMax`（5，取值 0–20）、`requestRetryBackoffMs`、`requestRetryBackoffCapMs`（30000）是请求级限流重试的部署值，刻意不进设置卡，且退避数组是整份替换而非合并。分工是「先问下游、无人接再自己来」：waterfall 上官方 `llm-retry` 愿意接的失败（码表内、次数未耗尽）归它，本包只接它放行的（码表外如 `QUOTA`、次数耗尽、`Retry-After` 超限）；「宿主有没有解析出 `retryPolicy`」不是分工线——llm 注册表对未配置的 provider 会补一份默认策略，那个判据恒真。要改部署值就写在本插件注册行的 `config:` 块，改值随重启生效。

## 需要外部提供什么

不需要：没有外部 CLI、解释器或凭据。请求级限流重试之上仍由官方重试层按各 provider 的策略处置（本包先让下游、下游放行才接手）。
